# Agilex 7 F-Series (2× F-Tile) Dev Kit Schematic — Walkthrough for Custom Board Design

Reference: `Agilex7 FPGA F-Series_2xF_Tile_DK`, doc 180-0330678-D1, device **AGFB027R24C2E2VR0**
(F-Series, 027 density, R24C package, tile speed 2, core speed 2, Extended temp, **V = SmartVID**).

This board is far more complex than a MACsec encryptor needs — dual DIMM, HPS daughter card, CXL,
PCIe x16 gold finger, dual QSFP/QSFPDD. Use it as a **pattern library**, not a template to copy whole.
Section 9 tells you what to prune.

---

## 1. Power architecture — the part that matters most

### 1.1 Two independent 12V inputs, hot-swap protected, then sequenced

Two power sources feed the board: **PCIE_EP_12V** (from the PCIe edge connector) and **12V_AUX**
(from a 2×4 ATX-style connector). Each goes through its own **hot-swap controller**
(MAX16550A / MAX16545B, QFN-20) before touching anything else — inrush current limiting,
overcurrent protection, and SMBus telemetry (voltage/current/fault) reported back over I2C.
A slide switch lets the board run in "bench mode" (AUX only) or "add-in card mode" (both rails present,
switch has no function).

**Takeaway for your board:** don't wire 12V straight to your regulators. A hot-swap controller in
front of every board-level power input is standard practice, not overengineering — it's what
survives connector hot-plug and reverse-connection events in the field.

### 1.2 Sequencing is done by MAX10, not by regulator power-up order

The **MAX10 CPLD acts as the system power sequencer.** It drives four enable groups —
`EN_G0`, `EN_G1`, `EN_G2`, `EN_G3` — and reads back `PWRGD_G0..G3` from each regulator stage
before asserting the next group's enable. This is the literal implementation of the "monotonic,
gated sequencing" requirement from the Power Management User Guide: it's not magic inside the
FPGA, it's a small controller (here, a MAX10; could be a cheap CPLD or even a sequencer IC on
your board) gating enables based on power-good feedback.

Rough order observed: **housekeeping rails first** (3V3_MAX10, 2.5V_MAX10, 1.8V_MAX10,
1.2V_MAX10 — these power the sequencer itself and its I2C/telemetry chain) → **SDM domain**
(VCCH_SDM, VCCL_SDM, VCCPLLDIG_SDM) → **core/transceiver rails** (VCC/VCCP core, VCC_HSSI_GXF,
VCCERT_FGT_GXF) → **I/O rails** (VCCIO_1V2, VCCIO_SDM_HPS).

**Takeaway:** you need a small always-on controller (MAX10, cheap CPLD, or a dedicated
power-sequencer IC) whose only job is: power itself up first from a simple rail, then gate every
other enable off PG feedback, in the right order. Don't try to sequence with RC delays alone.

### 1.3 SmartVID is implemented with LTC3888 — this is your reference circuit

The core VCC/VCCP rail (the one that must be SmartVID-adjustable) is generated by an
**LTC3888** (dual PolyPhase step-down with PMBus/SVID interface, I2C address **0x55**).
Its `SDA1/SCL1` pins connect **directly to the FPGA's SDM pins** `FPGA_1V8_SVID_SDA` /
`FPGA_1V8_SVID_SCL` — this is the literal SVID bus Altera's power management guide describes.
The same I2C bus is shared with MAX10's telemetry bus ("Agilex supports Multi-master" is noted
directly on the schematic), so SmartVID traffic and board telemetry coexist on one bus.

Output feedback uses a differential remote-sense pair routed back from the FPGA package pins
(`FPGA_VCCSENSE` / `FPGA_GNDSENSE`) — not sensed at the regulator — to correct for IR drop across
the board. Route these as a tight differential pair, away from noise.

**This is close to the most directly copyable circuit on the whole board for your project.** If
your device is a `V` (SmartVID) part, you need an LTC3888 (or equivalent PMBus/SVID-capable
regulator) wired exactly this way: SVID bus to the SDM pins, remote sense pair back from the
FPGA VCC/GND sense pins.

### 1.4 Everything else uses simple point-of-load regulators — don't overbuild these

The dozens of smaller rails (VCCPT, VCCH_SDM, VCCERT_FGT_GXF, VCCFUSEWR_GXF, VCCIO_1V2, etc.)
mostly use **ISL80101** (simple 4A synchronous buck, DFN-11) with a basic resistor-divider
feedback network (`Vout = 0.5V × (Rup/Rdn + 1)`) and soft-start cap. A couple of higher-current
rails (VCCPT, VCCERT_FGT_GXF/VCCCLK_GXF pair) use **LTC7132** dual-output digital PolyPhase parts
with their own I2C addresses (0x74, 0x75) for the same telemetry/config bus.

**Takeaway:** you don't need exotic parts for most rails. A basic synchronous buck with a
resistor-set output and a PG pin, fed into your sequencer's gating logic, covers the majority
of the rail count. Reserve the digital/I2C-programmable parts for rails where you actually want
runtime monitoring or margining.

### 1.5 Decoupling placement is systematic, not sprinkled

Two dedicated schematic sheets exist purely for decoupling, split by **placement zone**:

- **"Place these caps within FPGA cavity for VCC, VCCP"** — bulk caps physically under the package cavity.
- **"Place these caps around FPGA pin field for VCC, VCCP"** — a second ring around the ball field.
- **"Extra FPGA VCC Caps — Place on BOT periphery, 2-GND vias each cap gnd pad minimum"** and
  **"Extra FPGA VCC Caps — Place on BOT side in BGA field between PWR/GND vias"** — additional bulk
  capacitance woven directly into the BGA escape pattern, each requiring its own dedicated GND vias.
- F-Tile gets its own separate decoupling sheet, called out per-bank ("Place on left side near
  F-Tile Bank 12C", "Place BOT near VCC_HSSI_GXF pins", etc.) — every rail gets caps placed near
  the specific bank that consumes it, not lumped in one corner.

**Takeaway:** plan capacitor placement zones on your layout *before* routing, tied to specific
package regions and specific rails, exactly like this. This is the single most copyable layout
discipline on the whole board, and the cheapest to get right early.

## 2. Configuration & SDM

- **Two dual-die QSPI flash devices** (2 Gb each, so 4 total FPGA image slots — the schematic
  literally notes "AGILEX AGF027 Bit Stream size = 833.4Mbits, total FPGA image support = 4").
  Wired for **AS×4** (bit-banged quad SPI) as a secondary path, but the primary configuration
  path is **AVSTx16**, driven by MAX10 acting as configuration host.
- **MSEL strap table**, set by a physical DIP switch bank, directly off the schematic:

  | Config Mode | MSEL2 | MSEL1 | MSEL0 |
  |---|---|---|---|
  | JTAG | 1 | 1 | 1 |
  | AVSTx16 | 1 | 0 | 1 |
  | AS×4 Fast (CVP) | 0 | 0 | 1 |
  | AS×4 Normal | 0 | 1 | 1 |

  Put an equivalent strap header (or hard-wired resistors, if you know your final config mode)
  on your board — don't leave MSEL floating.
- **SDM pin usage is specific and documented per-pin** on this board: `SDM_IO0` = PWRMGT SCL,
  `SDM_IO1/2/3/4/6` = AVSTx8 data lanes (used for JTAG/status here), `SDM_IO5` = AS nCSO0,
  `SDM_IO7` = AS nCSO2, `SDM_IO11` = PWRMGT SDA, `SDM_IO16` = PWRMGT alert. This confirms:
  **SDM pin assignment is a board-specific constant you choose and then hard-code into your
  Quartus QSF** — there's no universal mapping. Decide yours early and keep it consistent between
  schematic and QSF.
- A **NIOS flash** (separate small QSPI, `W25Q64`) is provided purely for a soft Nios V processor
  image — irrelevant unless your design instantiates Nios V for housekeeping/control-plane logic.

## 3. Clock architecture — three-tier reference clock distribution

This is a good model for anyone needing multiple protocol-rate references (Ethernet + PCIe + CXL + memory).

1. **ZL30733** (IEEE 1588-capable clock generator, I2C address `0x70`) is the master clock IC.
   It fans out: `CLK_FPGA_100M` (general fabric reference), `ToD_MASTER_CLK_125M` and
   `PTP_SAMPLE_CLK_250M` (IEEE 1588 timestamping — relevant if your MACsec design ever needs
   PTP/timestamp-aware framing), DDR4 DIMM/component reference clocks, and — most relevant to
   you — **QSFPDD_REFCLK / QSFP_REFCLK** (the actual Ethernet port reference clocks) and
   CIPRI high/low reference clocks.
2. **Si53254** (2:1 differential clock mux/buffer, two instances) sits between the CXL/PCIe
   reference sources and the F-Tile, letting the board select between the local oscillator and a
   connector-supplied reference clock per port.
3. **Si52204** (PCIe-grade clock generator with selectable spread-spectrum, 0/0.25%/0.5% down-spread)
   generates the actual PCIe/CXL reference clocks with correct SSC characteristics for compliance.

**For your board:** you need at minimum tier 1 — a clean, low-jitter reference oscillator or
synthesizer feeding your F-Tile's Ethernet port reference clock pins, on the correct quad
(see §4). If you don't need PCIe/CXL, you can drop tiers 2 and 3 entirely and just feed the
100GE/25GE reference clock quad(s) directly from a single low-jitter oscillator per the F-Tile
Reference and System PLL Clocks IP requirements we discussed earlier.

## 4. F-Tile transceiver bank wiring — directly reusable for your MACsec port

**Bank 12C** on this board hosts CXL×4, QSFP-56 (4 lanes), and QSFPDD-56 (8 lanes) — all on the
same F-Tile bank, each with its **own reference clock pins per quad**
(`REFCLK_FGTL12C_Q0_RX_CH0...`, `REFCLK_FGTL12C_Q1...`, `REFCLK_FGTL12C_Q2...`,
`REFCLK_FGTL12C_Q3...`). This is concrete confirmation of what I flagged earlier abstractly:
**reference clocks are wired per-quad (4 channels), not per-lane, and not shared board-wide.**
Plan your reference clock fanout the same way — one clean differential reference pair landing
at each quad you actually use.

**Bank 13A** hosts the PCIe×16 EP interface with its own separate quad reference clocks
(`REFCLK_FGTR13A_Q0..Q3`) — a second, independent bank, confirming banks don't share reference
clock infrastructure either.

### The actual QSFP/QSFPDD port circuit (this is your template)

Each cage (QSFP-56 and QSFPDD-56 use nearly identical circuits) has:

- **TX/RX differential pairs routed directly from F-Tile balls to the cage connector** — no AC
  coupling caps on the board side. A schematic note explains why: *"DC blocking capacitors are
  in the module for RX and TX"* and *"zQSFP 100-ohm termination is implemented via the FPGA
  on-chip termination"* — so you don't add series caps or termination resistors on your board
  for the high-speed lanes; the module and the F-Tile's on-die termination handle it.
- **1 µH inductors** (DCR < 0.1 Ω) filtering the module's VCC/VCCTX/VCCRX supply pins, each with
  local bulk + high-frequency bypass caps placed close to the cage.
- A **TPS2557** (or similar current-limited load switch) gates module power, with `ILIM`
  programmed by a resistor per the datasheet's `I_OSmax/nom/min` formulas printed right on the
  schematic — gives you inrush/overcurrent protection on the optical module rail, which is cheap
  insurance against a bad module damaging your board.
- **ModSelL, ResetL, ModPrsL, IntL** control/status lines routed to FPGA GPIO with defined pull
  states (ResetL and LPMode pulled high in-module; ModPrsL grounded on the module when present;
  IntL is open-collector, needs a pull-up on your board).
- **I2C (SCL/SDA)** from the FPGA to the module for MSA EEPROM reads (module identification,
  DOM/monitoring) — shared with the board's general 3V3 I2C bus via level-shifting buffers.
- **FAULT/PWR_EN** monitored back through the same load switch, reported to MAX10 (or your
  equivalent housekeeping controller) for fault handling.

**This is the circuit to copy near-verbatim** for your 100G MACsec port(s) — it's a proven,
complete optical-module interface: power switch with current limiting, filtered supply, direct
high-speed pairs to the cage with no on-board AC coupling, and the standard MSA control/status/I2C
signal set with correct pull directions.

## 5. I2C — hub-and-spoke, MAX10 as master

Every peripheral IC on the board — clock generators, power regulators, EEPROMs, temp sensors,
hot-swap controllers — sits on I2C buses mastered by **MAX10**, with a documented address map:

| Device | Address |
|---|---|
| ZL30733 clock generator | 0x70 |
| Si52204 PCIe clock gen | 0x6A |
| MAC EEPROM | 0x57 / 0x5F |
| Cert EEPROM | 0x56 / 0x5E |
| Board temp sensors (MAX31730) | 0x38, 0x9A |
| LTC3888 (SmartVID core regulator) | 0x55 |
| LTC7132 regulators | 0x74, 0x75 |
| PCIe/AUX hot-swap controllers | 0x42, 0x40 |
| DDR4 DIMM SPD | 0xA0, 0xA1 |

**Takeaway:** design your board's housekeeping around one central I2C master (your MAX10
equivalent, or a small MCU) with a clean address map document from day one — you will have far
fewer devices than this board (no dual DIMM, no HPS, likely one or two optical cages), but the
pattern — one master, documented addresses, buffered/level-shifted where voltage domains differ
(note the `PCA9306` level-translating I2C buffers used between 3.3V and 1.2V/1.8V domains here) —
is exactly what you want.

## 6. Bank/pinout planning notes worth copying

- The schematic explicitly documents **which banks migrate between package variants**
  ("Bank 3B is not available in Agilex FM76... no IOs will be used to support migration from
  FM86 → FM76", similar notes on Bank 2E, Bank 3C). If there's any chance you'll need a smaller
  or larger package variant later (cost reduction, or a bigger device for the 400G upgrade path),
  **avoid using banks that don't exist on your fallback/upgrade package**, and mark it in your
  own pin-planning notes now, the same way this schematic does.
- Bank 3A carries a mix of general IO, AVSTx16 configuration data, 1PPS test SMAs, and QSFP/LED
  control signals — a reminder that config, timing, and general GPIO often end up sharing a bank;
  plan bank budgets with margin, not exactly-what's-needed.

## 7. DDR4 subsystem — lower priority for you, but two patterns worth noting

You likely don't need external DRAM for a MACsec/crypto datapath (small SA tables, replay windows,
and PN counters fit comfortably in on-chip M20K/eSRAM). If you do need memory (e.g., large SA
tables, packet buffering for store-and-forward), two patterns from this board are worth keeping:

- **SPD EEPROM addressing and VREF/VTT generation are per-DIMM**, with dedicated small buck/LDO
  regulators (TPS51200-class) generating VTT and VREF locally, right next to the DIMM connector.
- The board also supports **soldered-down DDR4 components** as an alternative to DIMM sockets
  (5× `MT40A2G8VA` components forming a wide bus, with shared VREFCA/VTT generation) — for a
  ruggedized defense product, soldered-down memory is usually preferable to a socketed DIMM
  (better vibration/shock tolerance, no connector reliability risk). If you need memory at all,
  lean toward the component approach, not a DIMM socket.

## 8. HPS IO-48 daughter card, USB-BlasterII, CXL, PCIe×16 gold finger

These are dev-kit conveniences, not things your production encryptor needs:

- **HPS daughter card connector** — only relevant if your device variant has HPS and you intend
  to run embedded Linux/control-plane software on the ARM cores. If your OPN has no HPS
  (Fabric code without HPS, as your finalized part may be), this entire subsystem drops out.
- **USB-BlasterII Phy** (CY7C68013A) — this is a full on-board JTAG programmer circuit. Useful
  for a lab bring-up board; on your production board you more likely want a simple JTAG header
  and program via an external Blaster, unless field firmware updates over USB are a real
  requirement.
- **CXL connector, PCIe×16 gold finger** — drop unless your programme requires a host interface
  over PCIe/CXL. If it does, note it changes your device selection (needs P-Tile or R-Tile in
  the package) as flagged earlier.

## 9. What to actually keep for a minimal 100G MACsec encryptor board

| Subsystem | Keep? | Notes |
|---|---|---|
| Hot-swap-protected power input | **Yes** | Even a single 12V input deserves this |
| MAX10 (or equivalent) sequencer | **Yes**, scaled down | Fewer rails, but same PG-gated pattern |
| SmartVID LTC3888-class regulator + SVID wiring | **Yes, if OPN is a V/E/X part** | Copy §1.3 closely |
| Simple ISL80101-class bucks for minor rails | **Yes** | Don't over-spec these |
| Decoupling zone discipline | **Yes** | Cheapest thing to get right, biggest payoff |
| QSPI config flash + MSEL strap | **Yes**, 1–2 images not 4 | Simpler flash, same strap logic |
| SDM pin plan | **Yes** | Choose and document your own mapping |
| ZL30733-class master clock (tier 1 only) | **Yes**, simplified | Drop PCIe/CXL clock tiers if unused |
| QSFP/QSFPDD port circuit | **Yes — copy closely** | This is your Ethernet port, directly |
| I2C hub-and-spoke housekeeping | **Yes**, smaller address map | Document your own table now |
| Dual DDR4 DIMM + component | **Probably not** | Only if SA-table/buffering size demands it |
| HPS daughter card | **Only if OPN has HPS and you need it** | |
| USB-BlasterII onboard programmer | **Optional** | JTAG header alone may suffice |
| CXL / PCIe×16 gold finger | **Only if host interface is a real requirement** | Changes device selection if added |

This gives you a board with maybe a quarter of this schematic's page count, built from the same
proven subsystems, sized to what a MACsec encryptor actually needs.
